## 2026-10-10 カードの本当の価値を測る（card-value）と銀行家の調整（公開済み）

- 新ツール `npm run card-value`（同じ CPU 同士で片方がカードを禁止/優先、各 600 試合、誤差 ±2%）。
  `BALANCE='{...}'` で数値を上書きして試せる。40 試合 2 秒で速い。
- 結果: 銀行家は優先すると勝率 74.8%（突出）、建築家は禁止すると 27.2%（必須級）。
  衛兵は禁止すると 60.8%（使うと損）、買収者は優先すると 29.1%（無価値）。
- 銀行家を（収入 11 + 1/件）→（6 + 2/件）に。禁止 43.3% / 優先 43.9%。「物件が増えるほど稼ぐ」を残した。
- 買収者の枚数 3、コスト 2、衛兵コスト 1、徴税官 8 は試したが効果なし（衛兵は禁止 60% のまま）。
  **数値の調整では直らない**と判断。→ `design-next.md`（アップグレード/買収など、お金の出口と干渉手段を増やす）。
- サブエージェント 2 件の調査結果は backlog に反映（継続の仕組み、待ち時間 7.6 秒/手番 など）。

## 2026-10-10 徴税官を「次の収入から引く」効果に変更（公開済み）

- 計測（`npm run lab -- 100`、各組 100 試合。**誤差 ±5% 程度**なので勝率の小差は信用しない。カード使用率は安定）:

| 指標 | 変更前 | 変更後 |
|---|---|---|
| 徴税官の使用率 | 9.7%（妨害特化でも 4.7%） | 15.8%（妨害特化 11.0%） |
| 採掘師 | 33.9% | 30.6% |
| 銀行家 | 28.2% | 24.7% |
| 先手勝率 | 49.5% | 50.7% |
| 平均ターン数 | 15.4 | 17.2 |

- 原因: 相手は自分の手番でコインを使い切るので、「今の手持ち」を削る旧徴税官は 24.8% しか効かなかった。
  収入は相手の手番の頭で入るため、そこから引く形（`pendingTax`、手持ちを上限にマイナスにしない）にした。
- 失敗した途中案: 先に `pendingDebt`（高利貸と同じ借り）で試したら、使用率が 2.6% に落ちた。
  CPU の評価関数が「相手に課した借り」を数えていなかったため。`evaluate.ts` に自分・相手の `pendingTax` を足して直した。
  **教訓: 効果を変えたら、CPU の評価関数もそろえる。さもないと計測が「CPU の盲点」を測ってしまう。**
- バックアップ: `autopilot/001-before-harass-rework`。
- 残り: 封鎖者 4.8%、買収者 8.5%（基準は 5%以上）。建築家 10.7%。
