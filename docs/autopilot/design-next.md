# 次の拡張の設計（2026-10-10 ユーザー案 + 実測）

## 動機（実測）

`npm run card-value`（同じ CPU 同士で片方がカードを禁止/優先）で、お金系（銀行家・建築家・採掘師）が圧倒的、
妨害・防御の 4 枚（衛兵・買収者・封鎖者・伝令）は使うと損かほぼ無価値だった。
数値調整だけでは「ワンパターン」は直らない。**お金を使う先と、相手に干渉する手段を増やす**。

## ユーザー案（採用順）

### 1. 施設のアップグレード + 物件の買収（最優先。核の「読み合い」を直接強くする）

- **アップグレード**: 自分の物件を、基本の建設費と同額で 1 段上げる（最大 Lv2）。
  VP と効果が増える。Lv2 の値は `balance.ts` の表で持つ（ロジックに数字を書かない）。
- **買収**: 相手の物件を、**それまでに払われたコインの合計 + 1** で奪える。
  例: 10 で建てた物件 → 11 で買収。さらに 11 で買われた物件 → 12。
  10 で建てて 10 でアップグレードしたら合計 20 → 21 で買収。
  - 払ったコインは**元の持ち主に入る**（コインの総量は増減しない。買収は VP と効果の移動）。
  - 買った物件は、買収した側の「払われた合計」になる（次の買収はその +1）。Lv は保つ。
  - 建てた/買収したターンに同じ物件を再び買収されないよう、**同じ区画は 1 ターンに 1 回まで**。
  - 衛兵は買収も防ぐ（次の自分のターンまで）。封鎖者で効果を止められた物件も買収できる。
  - 城壁は「徴税官・封鎖者を受けない」のまま（買収は防がない）。
- 買収・アップグレードは**手札のカードを使わない行動**（建設と同じ行動）。
  これで、お金系カードで貯めたコインの出口が増え、「貯めて買収する」「奪われる前に上げる」の読み合いが生まれる。

### 2. 同じカードを 1 ターンに複数回使える

- 現状は 1 ターン 1 回まで。使える形にして、**自己対戦で壊れないか**（銀行家・採掘師の連打）を測る。
  投資系は「次のターン」に効くので永久機関にはならない。
- 連打を許すと、同じカードが手札に複数枚ある場合や、使ったカードが待機列へ回る仕様と衝突する。
  実装前に reducer の `usedThisTurn` と `canUseCard` の意味を確認すること。

### 3. 区画の独占ボーナス / 物件と人物カードの連携 / 物件の種類を増やす

- 市場 10 区画を**数個のエリア**に分け、エリア内の物件を 1 人が独占したら追加ボーナス。
- 物件が特定の人物カードを強める（例: 採掘師は石切場があると +X）。逆も。
- 新しい物件・効果は、`standards.md` の合格ライン（死にカードなし）を満たすまで測る。

### 4. カードのレベルアップ（使用回数）/ ドラフトとデッキ構築

- 使うほどカードが強くなる（Lv ×3 程度）。ゲームを跨いで進行する要素なので、保存形式の設計が要る。
- 新しい人物カードが増えたら、**ドラフト**（3 択を 10 回など）で毎試合のデッキを作る。
  デッキは今は 10 枚固定。必要なら変えてよい。
- これは**継続の仕組み**（収集・育成）にもなる。ただし 1〜3 で面白さの土台ができてから。

## 合格ライン（変更後に必ず測る）

- `npm run typecheck` と `npm test` が通る。
- `npm run card-value -- 400`: 全カードで「禁止 40〜60%」「優先 40〜60%」に近づける（現状は銀行家・建築家・採掘師が突出、衛兵・買収者が逆に弱い）。
- `npm run lab -- 100`: 先手勝率 47〜53%、4 つの性格の総合勝率 45〜55%。
- 買収が**多すぎず少なすぎず**使われる（1 試合あたり 0.5〜3 回を目安にして、実測してから決める）。
