# PvP モード設計

日付: 2026-09-16
対象: `city-builders`

## 背景・目的

通信なしの 1 画面対戦モードを追加する。プレイヤーはあお（先攻・既存の
`'you'`）とあか（後攻・既存の `'cpu'`）に分かれ、スマホを交互に渡してプレ
イする。色の割り当ては既存 CSS の所有者トーン（`--owner-you` が青系、
`--owner-cpu` が赤/橙系）にそのまま合わせている。ターン終了時、画面上の
「相手帯（上）」と「自分の帯＋手札（下）」をスライドで入れ替え、次の手番
側が下に来るようにする。

## スコープ

- ホーム画面に「2人で対戦」を追加し、既存の vs CPU（やさしい/ふつう/
  つよい）と並べる。
- 新規 `PvpGame.tsx` を追加。CPU の 1 手ずつの進行演出（`cpu-turn.ts` 系）
  は使わない。
- ゲームロジック（`reducer.ts` / `types.ts` / `selectors.ts` / `setup.ts`）
  は無改造。AI（`src/ai`）は呼ばない。
- 対象外: ネットワーク対戦、3 人以上、ハンドオフ確認画面、CPU 戦績への
  PvP 結果の混入。

## 型・データ

- `PlayerId`（`'you' | 'cpu'`）は変更しない。先攻＝`'you'`＝あお、後攻＝
  `'cpu'`＝あかの固定割り当て。内部 ID は変えず、表示ラベルのみ「あお」
  「あか」にする（既存の建物トーン `--owner-you`＝青系、`--owner-cpu`＝
  赤/橙系と一致させるための割り当て）。
- `state.current` は既存の `reducer.ts` がそのまま面倒を見る（手番側を
  切り替えるロジックは `endTurn` アクションで完結しており、対 CPU でも
  対人でも同じ）。

## コンポーネント変更

### `Board.tsx` / `CoinBar.tsx` / `Hand.tsx`

- `'you'` 決め打ちの箇所（`state.players.you...`、
  `buildCostFor(state, 'you', ...)`、`handOf(state, 'you', ...)` など）を
  `viewer: PlayerId` prop に置き換える。
- `Game.tsx`（vs CPU）は常に `viewer="you"` を渡すだけで、既存の挙動・
  見た目は一切変わらない。

### `InfoBoard.tsx`

- 変更なし（既に `owner: 'you' | 'cpu'` を受け取る汎用コンポーネント）。

### 新規 `PvpGame.tsx`

- `Game.tsx` を土台に、CPU 進行（`useEffect` で `cpuTurn` を進めるロジッ
  ク、`cpu-turn.ts` 呼び出し、`OpponentStrip` の行動ログ表示）を除いた
  版。
- 上部（相手帯）: `InfoBoard` を直接使い、名前「あお／あか」、コイン、
  VP、残りターン数のみを表示（行動ログ・カードフラッシュは無し）。
- 下部（自分帯）: 既存の `CoinBar` + `Hand` を `viewer={state.current}`
  で使う。
- 中央の市場 `Board` はそのまま共有（入れ替えない）。`viewer` は建設可否
  判定などに使うため `Board` にも渡す。

## ターン交代アニメーション

- `endTurn` 押下時、即座に `reduce()` を呼ばず、まず「入れ替え中」フラグ
  を立てて操作を無効化する（対 CPU 版の `cpuActing` と同じガード方式）。
- 上の情報帯ブロックと、下のコインバー＋手札ブロックを Motion で
  スライドさせて位置を交換する（300〜450ms 程度）。
  - 実装は 2 ブロックを絶対配置し、`animate={{ y: ... }}` で上下に移動
    させながらクロスフェードする形を想定。詳細な数値・イージングは実装
    時に既存アニメーション（`Hand.tsx` の spring 設定等）に合わせて調整
    する。
- アニメーション完了後に実際の `reduce(state, { type: 'endTurn' })` の
  結果を反映し、新しい `state.current` 側の帯を下に描画、フラグを解除
  する。
- ハンドオフ確認画面は入れない（このゲームは手札が公開情報のため、覗き
  見の不公平が発生しない）。

## 勝敗・記録

- 終了シートの文言を PvP 時は「あおの勝ち／あかの勝ち」（引き分けは
  そのまま）に出し分ける。
- `saveProgress` / `loadProgress`（`storage.ts`）の `wins`/`losses`/
  `lastDifficulty` は vs CPU 専用の戦績なので、PvP の結果はここに記録
  しない。

## エラーハンドリング・エッジケース

- 「あきらめる」メニューは両モード共通の挙動（確認シート→ホームへ）で
  流用する。
- 入れ替えアニメーション中の連打・二重タップは操作無効化フラグで防ぐ
  （対 CPU 版の `cpuActing` と同じ扱い）。

## テスト

- `reducer.ts` 等のゲームロジックは無改造のため、既存の `__tests__` の
  ユニットテストはそのまま通る想定（変更なし）。
- 手動確認（ブラウザプレビュー）: ホームから「2人で対戦」→あおの手番で
  カード使用・建設→終了→スライド演出→あかの手番に切り替わり同様に操作
  できること→どちらかが勝つまで一周し、終了シートの文言が「あお/あかの
  勝ち」になることを確認する。
