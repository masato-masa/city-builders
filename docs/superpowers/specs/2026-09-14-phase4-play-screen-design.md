# Phase 4 プレイ画面の作り込み 設計仕様書

作成日: 2026-09-14
前提: `docs/superpowers/specs/2026-09-14-city-builders-design.md`（ゲーム本体の仕様）

---

## 1. 何を作るか

プレイ画面を、**盤面と素材を主役にした見た目**に作り替える。ゲームのルールは一切変えない。

Phase 4 として当初挙げていた 4 つのうち、**このサイクルで扱うのは 1 と 2 だけ**。

| # | 塊 | このサイクル |
|---|---|---|
| 1 | レイアウトと寸法 | **やる** |
| 2 | 質感（色・立体感・文字） | **やる** |
| 3 | 演出（アニメ・効果音・振動） | やらない。レイアウトが固まってから |
| 4 | 素材の量産（残り 14 枚） | やらない。1 枚できるたびに差し込む |

素材は**城塞・商館・盤面の 3 枚が試作済み**。残りは空き地のまま遊べる形にして、後から差し替える。

---

## 2. いまの画面の何が問題か

公開版を実機幅で確認して分かったこと。

| 問題 | 原因 |
|---|---|
| 手札が画面の 6 割の位置に浮き、下に 190px の空白 | `shared-ui` の `.play` が `justify-content: center` で全要素をひと塊にして縦中央へ寄せる |
| 盤面の上に 150px の空白 | 同上 |
| 市場が画面幅の 7 割しか使わず、1 マス 68px で窮屈 | グリッドを中央寄せしているため |
| コインバーが小さなピルで、最重要情報に見えない | 全幅になっていない |
| 「ターンを終える」が手札より下 | 参考画面と上下が逆 |
| カードが横長（約 76×62） | 実測した参考値は 68×84 の**縦長** |

`.play` は 4 本のゲームで共有する生成物なので**直接編集しない**。代わりに `.play` の中にこのゲーム専用の器を 1 枚入れ、その器が `flex: 1` で領域を占めて、中で縦を配り直す。`.play` の `justify-content: center` は子が 1 つで伸びきるため影響しなくなる。

## 3. 画面の骨格

```
行1   [戻る]      シティビルダーズ      [?]          ← shared-ui（設定は Phase 5 で戻す）
行2   ターン 7/20 ・ あなた 8VP ・ CPU 6VP ・ 残り 4  ← status-bar
──────────────────────────────────────
相手エリア   CPU アイコン ・ コイン ・ 物件数と VP
──────────────────────────────────────
盤面         縦横比 3:4 の土地。10 区画に建物が建つ
──────────────────────────────────────
コインバー   [コイン] 19    次のターン +12    [終了]
──────────────────────────────────────
手札         [次] | [1][2][3][4]
```

### 縦の配分（375×812 で計算）

| 要素 | 高さ |
|---|---|
| ヘッダー 1 行目 | 56 |
| ステータスバー | 30 |
| 相手エリア | 44 |
| **盤面** | **残り全部（488）** |
| コインバー | 48 |
| 手札 | 110 |
| 外周の余白 | 上 16 / 下 20 ＋ セーフエリア |

盤面は幅いっぱい（343）で縦横比 3:4 なら 457 になり、488 にちょうど収まる。
**縦が余らない。** これが間延びを解消する仕掛け。

**背の低い画面（375×667 など）では盤面が縦に収まらない。** その場合は盤面を縮めて中央に置く
（`flex: 1; min-height: 0` の器の中で、`aspect-ratio: 3 / 4; max-width: 100%; max-height: 100%`）。
区画の座標は盤面に対する割合なので、盤面が縮んでも配置は崩れない。

### 「ターンを終える」をコインバーに入れる理由

コインバーは「今いくら持っていて、次いくら入るか」を見る場所で、**ターンを終える判断と同じ情報**。
視線が一致する。そして手札を最下段に置ける。参考画面はリアルタイム制で終了ボタンが存在しないため、
ここは借りられない。

## 4. 盤面

### 盤面の地

`refs/art/field-user.png`（ユーザー作成）を使う。石畳の広場で、彩度が低く均質。
**建物が確実に主役になる**ので、自前で生成したのどかな草地よりこちらが目的に合う。

画像は 1024×1536（縦横比 1 : 1.5）。盤面の枠は 3 : 4 なので、`object-fit: cover` で
上下を約 11% 切って収める。中央付近の金色の線は残る。

### 区画の配置

10 区画を **横 3 / 4 / 3 の千鳥**に置く。行を揃えないので一覧表に見えず、土地の見取り図になる。
座標は盤面に対する割合で持ち、`position: absolute` で置く。**建っても壊れてもレイアウトは 1px も動かない。**

`balance.market` の配列順（index 0〜9）が、そのまま区画 0〜9 に対応する。
現在の並びでは商館 3 件が上段に、城塞 2 件が中段右と下段中央に来る。

ステージを追加するときは、配置表を 1 つ足す。

### 建物の大きさ

素材ごとに画像の縦横比が違うので、**幅を揃えると横長の建物が小さく見える**。試作で実際に起きた。

| 素材 | 不透明部分の縦横比 | 底辺の幅（画像幅比） |
|---|---|---|
| 城塞 | 1 : 1.06 | 93% |
| 商館 | 横長 | 55% |

素材ごとに `scale`（区画幅に対する倍率）を持たせ、`scripts/audit-art.mjs` が
**不透明部分の面積**を測って初期値を出す。盤面プレビューを見て微調整する。

### 未建設と建設済みの見せ方

- **未建設**: 空き地。薄い土台の輪郭と、**コストを金色**で表示
- **建設済み**: 建物の素材を置き、**足元に所有者色の土台**（円または旗）を敷く。表示は **VP に変わる**

**建物そのものに色を被せない。** 城塞の屋根が赤いので、所有者色を乗せると素材が濁る。
足元の土台なら、素材を汚さずに所有者が一目で分かる。

「いくら払うか」と「いくら稼いだか」が同じ場所で入れ替わる。

### 封鎖中の表示

Phase 2 で入れた `opacity: 0.4` を維持する。詳細シートに理由の一行も出す。

## 5. 手札

実測した参考値をそのまま使う（`refs/measured.md`）。

| 対象 | 値（CSS） |
|---|---|
| カード 1 枚 | 68 × 84（**縦長**、比 1 : 1.235） |
| カードの間隔 | 5 |
| コストバッジの直径 | 19（カード下端中央に**重なる**） |
| 手札パネルの高さ | 153（本作は 110 に圧縮。盤面に縦を回すため） |

- **next は 1 枚だけ**、左に小さく。ラベルは「次」
- コストは**カード下端に重なる金の丸バッジ**。カード内の数字ではない
- 使えないカードは沈める（このターン使用済み／コスト不足とも同じ）

4 枚 × 73（68＋5）＋ next 88 ＝ 380。375 幅でも収まる。

## 6. 色

**盤面と手札はこのゲーム専用の色域を持つ。** ヘッダー・シート・ホームは `shared-ui` のまま。
CLAUDE.md が「盤面の色は共通化しない」と定めているので規約違反にならない。

素材から実測した値。

| 対象 | 色 |
|---|---|
| 盤面の平均 | `#9e965c` |
| 盤面の暗い側（芝） | `#7a8847` |
| 盤面の明るい側（土・石畳） | `#c1a26d` |
| 城塞の平均 | `#a5716d` |
| 商館の平均 | `#995d47` |

盤面が**暖色**なので、UI の地は**寒色で暗く**して離す。

| 用途 | 値（初期案） |
|---|---|
| 手札パネル・コインバー・相手エリアの地 | `#1e2a33` |
| その一段下 | `#16202a` |
| コインの金 | `#ffc83d` |
| 自分の所有色 | `#2f7fd0` |
| CPU の所有色 | `#d2622a` |

**所有色は実装後に必ず検証する。** CPU の橙は盤面の土（`#c1a26d`）と近い。
CLAUDE.md の基準どおり**相対輝度で 14% 以上離れている**ことを測り、足りなければ土台に濃い縁を足すか色を変える。

## 7. 質感

参考画面の立体感は、素材だけでなく UI の作りにも出ている。CSS で再現できる範囲を明記する。

| 要素 | 方法 |
|---|---|
| 立体的なボタン（上面が明るく下に厚み） | `box-shadow` の多重掛け＋内側ハイライト |
| 太い縁取り文字 | `-webkit-text-stroke` ＋ `paint-order: stroke fill` |
| カードの枠・光沢 | グラデーション＋内側影 |
| 盤面の奥行き | いまは平らなまま。傾けるのは Phase 5 で判断する |

**レイアウトを動かす装飾は入れない。** 影・グラデーション・縁取りは要素の寸法を変えないので安全だが、
`border` の太さや `padding` を状態で変える表現は使わない。

## 8. 素材の作り方

試作で確立した手順。残り 14 枚はこの型で量産する。

### 生成の手順

1. **新しい会話を開く。** 失敗作が会話に残っていると次の生成がそれを引きずる
2. **見本を添付する。** 質感を伝える手段としてこれが一番速い。添付してよいのは
   （a）自分たちの既存素材（画風を揃えるため）と（b）目指す質感の参考画面
3. **否定条件を必ず書く。** 添付したものに引っ張られるのは当然なので、引っ張られたくない部分を
   名指しで禁止する（下記）
4. 数量・比率・角度は**漢数字**で書く。ChatGPT の入力欄は半角数字を落とす
5. 生成を指示する文を**先頭**に置く。条件を並べすぎると生成せず「指示してください」と返ってくる
6. 取り出しは `fetch(img.src, {credentials:'include'})` から Blob を落とす

### 否定条件の書き方

参考画面を添付するときは、**質感だけを借り、意匠と構図は借りない**ことを明示する。
試作 1 回目でこれを書かなかったため、川と橋を左右対称に配した「アリーナ」が出てきた。
**添付が悪かったのではなく、制限が足りなかった。**

盤面を作るときに効いた否定条件:

```
・添付画像に写っている建物・地形・意匠は一切模写しないでください。
  参考にするのは質感（立体感・陰影・光の向き・色の乗り方）だけです。
・川、水路、池、橋は描かないでください。
・左右対称にせず、中央に境界線を作らず、競技場・アリーナ・ゲーム盤に見えないようにしてください。
・建物、人物、動物、乗り物、文字、ロゴ、枠線は描かないでください。
```

新しい素材を作るたびに、**その素材で借りたくない要素を名指しで足す**。

### 守ること

- 素材はすべてオリジナル。既存ゲームの建物・地形・意匠を模写しない
- 出来上がったものが参考画面に似すぎていないか、**必ず目で確かめる**。
  似ていたら否定条件を足して作り直す
- 背景は完全な透明。地面・台座・影の板・枠線・文字を入れない

### プロンプトの型

```
画像を一枚生成してください。同じゲームで使う建物アセットの◯つ目です。
添付は既存の素材で、これと並べて置くので、画風・光の向き・彩度・質感を完全に揃えてください。

描くのは〈建物の説明〉。〈形の特徴〉。
城塞より背を〈高く／低く〉、横に〈狭く／広く〉してください。
全体をずんぐりさせ、細部は削り、とても小さく表示しても何か分かるシルエットにしてください。

質感は添付と同じく、輪郭線を使わず、面の陰影とハイライトと柔らかい落ち影で立体を見せる、
粘土やプラスチックの模型のようなつるりとした質感。光は上方からの柔らかい暖色光。
背景は完全な透明にして、地面・台座・影の板・枠線・文字は入れず、被写体のみ。
正面からやや見下ろした角度。縦横比は、横を〈漢数字〉としたとき縦が〈漢数字〉。
```

### 常設のツール

| ツール | 用途 |
|---|---|
| `scripts/extract-ref-colors.mjs` | 参考画面から色・寸法を数値で抜く（`crop` / `pick` / `scan`） |
| `scripts/board-preview.mjs` | 盤面に建物を重ねて実機の大きさで確認する。区画座標と倍率を変えて即試せる |
| `scripts/audit-art.mjs` | **新規**。素材の縦横比・底辺の幅・面積・透明率を測り、`scale` の初期値を出す |

## 10. 完了の定義

- [ ] 実機幅（375 と 393）で、盤面が縦を使い切り、上下に大きな空白が無い
- [ ] 手札が画面下端に固定され、カードが縦長（68×84）
- [ ] コストがカード下端の丸バッジで出る
- [ ] 盤面の 10 区画に、未建設はコスト、建設済みは建物と所有者色の土台と VP が出る
- [ ] カードを使っても建物が建ってもシートを開閉しても、**レイアウトが 1px も動かない**
- [ ] 所有色が盤面に対して相対輝度で 14% 以上離れていることを測定で確認した
- [ ] 背の低い画面（375×667）でも盤面が収まり、横スクロールが出ない
- [ ] GitHub Pages に反映され、実機で確認した
